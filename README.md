# Project Workflows

研究や改善活動で、候補の調査から実験、知見の報告までを進めるためのAgent Skillsです。
人間が取り組む方向を決め、エージェントがその範囲で方法を探り、判断に必要な根拠をまとめます。

## 基本の流れ

1. **方向を決める。** 人間が対象分野や改善方針、達成したいこと、使える時間・資源を伝えます。
2. **候補を調べて試す。** エージェントが検証する問いと作業に分け、独立した調査や実験を並列に進めます。
3. **結果から次を決める。** 比較できる条件で結果を確かめ、予算内で追加検証や打ち切りを判断します。
4. **報告を読んで選ぶ。** 人間が手法ごとの報告書を読み、有望な方法を見定めます。

エージェントは指定された方向と制約の中で探索を進めます。方向の変更や予算の拡大は、人間の判断に戻します。
並列実行には利用環境のエージェント・ジョブ機能を使い、利用できない場合は順に進めます。

## 成果物

人間が最初に読むのは、**手法ごとに1本のPDF**です。
冒頭で手法の要点、有望かどうかの判断、主な根拠と限界を把握でき、関心があれば同じPDFの後半で
仕組みや実験条件、結果、出典を詳しく読めます。対象分野の基礎を知っている人が、過去の会話を知らずに
理解できる報告を目指します。

採否を別々に判断する手法は別のPDFにし、同じ手法の条件違いや再試行は1本にまとめます。
PDFはLaTeXで生成した報告時点の固定版として残し、生成用のtexは納品しません。
再報告するときは新しい版を作ります。PDFの生成には、対象言語に対応したLaTeX環境が必要です。

調査・実験の補助記録や作業状態はMarkdownで残し、元のコード・設定・データへつなぎます。
既存の保存先や計画管理を使い、次の探索や別セッションでの再開に役立てます。

## スキル一覧

| Skill | 役割 |
| --- | --- |
| [explore-methods](skills/explore-methods/SKILL.md) | 候補の調査・設計・実験を配分し、結果の判断と手法ごとの報告まで進める |
| [record-knowledge](skills/record-knowledge/SKILL.md) | 調査や実験で得た知識を、条件や根拠とともに記録する |
| [curate-knowledge](skills/curate-knowledge/SKILL.md) | 散らばった知識や重複する説明を、根拠を保って整理する |
| [continue-work](skills/continue-work/SKILL.md) | 作業状態を保存し、実際の進捗と照合して続きを進める |

探索全体を任せるときは `explore-methods` を使います。記録・整理・再開だけを依頼するときは、
対応するスキルを使えます。各スキルは独立して利用でき、ほかのスキルの導入を前提としません。

## 使い始める

`skills/` から使いたいスキルのフォルダ全体を、お使いのエージェントのSkills保存先へ配置します。
ローカルの変更をそのまま使う場合は、シンボリックリンクでも参照できます。

依頼では、取り組みたい対象と目的、評価方法、使える時間や資源を伝えます。

```text
$explore-methods 指定した分野・改善方針の中で候補を調査し、実験で比較してください。
予算内で有望な方法を見定め、手法ごとの判断用PDFにまとめてください。
```

途中から続ける場合は、対象の作業を指定して `continue-work` を呼び出します。
記録や保存先の詳しい扱いは、[構成と設計判断](docs/architecture.md)を参照してください。
