# 初版の実装と検証

更新: 2026-10-16。状態: 作業中。作業先: project-workflows、main。

## 目的と完了条件

記録・統合・再開を支える独立した3 SkillsをMITで公開する。
公式形式の検証、単独インストール、隔離した合成プロジェクトでの行動検証、
公開対象の機密情報・ライセンス確認、GitHubへのpushまで完了する。
ユーザーは設計判断・実装・テスト・Public作成・commit/pushを承認済み。
参考プロジェクトは読み取り専用。その内容・データ・固有の設定は公開しない。

## 設計

`skills/record-knowledge/` はArchitecture・Experiment・Researchの記録を担当する。
`skills/curate-knowledge/` は関連する根拠を探し、統合して不要な文書を削除する。
`skills/continue-work/` は既存の進捗管理を使ってチェックポイントと再開を扱う。
既存の配置と言語を尊重する。新規プロジェクトの既定は `docs/architecture/`、
`docs/experiments/`、`docs/research/`、一時的な作業は `.work/<task>.md`。
必要になったファイルだけ作る。現在の説明と歴史的な観測を混ぜない。

比較した代案:
- 1 Skillにすべて入れると、記録時にも統合・削除の判断が混ざる。
- タイプごとの細分化や独自台帳は、発見コストと同期箇所を増やす。
- 3つの責務に分け、必要な形式だけ参考文書で読む構成を採用する。

実験管理基盤を正本として参照し、設定・生成commit・解析commit・run ID・
データ/評価の版・成果物の所在を失わない。欠落はunknownとして明示する。
削除は対象範囲内で、固有の根拠を現存文書へ引き継ぎ、Git履歴と参照を確認してから行う。
継続性はディスクに保存した最新状態に基づく。常駐処理、独自archive、DB、
セッションログの自動収集、ホスト設定の自動改変は実装しない。

## 実装順序

- [x] 空のPublicリポジトリを作成し、ローカルに接続する。
- [x] 公式仕様、既存Skills、指定された3プロジェクトを調査する。
- [ ] 合成シナリオを用意し、Skillsなしの独立エージェントで基準動作を観察する。
- [ ] record-knowledgeを作成し、同じ入力の独立検証を実施する。
- [ ] curate-knowledgeを作成し、証拠・失敗・参照・未追跡文書の保全を検証する。
- [ ] continue-workを作成し、古いチェックポイント・複数タスク・既存計画との共存を検証する。
- [ ] インストール手順、使用例、出典と設計判断、検証手順を整える。
- [ ] 公式validatorとパッケージ検査をCIに接続し、実行する。
- [ ] 独立レビュー、公開ファイル確認、commit/push、リモートCIを確認する。
- [ ] 完成した構造と検証結果を長期文書に移し、この作業メモを退役する。

各Skillの完了判定: 名前・description・自己完結性・参照・行動検証・
想定外動作の修正と再検証を確認する。文言一致テストで行動品質を代用しない。

## 現在地と次の行動

Public作成済み。参考資料は一時領域でのみ閲覧した。
次は合成の実験記録・重複文書・中断作業を使った基準動作の検証。
ネットワークと `.git` 変更はsandboxの外側で実行する必要がある。
認証情報やPrivate文書は公開ファイルに含めない。
