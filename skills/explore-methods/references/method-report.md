# 判断用PDFの作り方

一つの手法について、判断の要約と詳細を同じPDFに収める。指定分野の基礎知識を前提にできるが、
個別手法の用語・記号、問題設定、比較対象は説明する。会話や別ファイルを読まなくても理解できるようにする。
言語は依頼に合わせる。ページ数を埋めるための一般論や作業日誌は加えない。

## 最初のページ: 続けて読む価値を判断できる内容

表紙だけのページを置かず、手法名、報告日・版、対象の問題を示して本文を始める。
次を短い文章と必要な表でまとめる。

- **判断**: 有望・見送り・判断保留などの推奨と理由。調査のみ・予備実験・追加検証済みなど、根拠の段階。
- **仕組み**: 何を変え、なぜ効くと考えたか。比較対象との差を読者の言葉で説明する。
- **主要な根拠**: 条件をそろえた基準と候補の値、指標の向き、試行数、ばらつきや失敗。
  実験していなければその旨と、文献から期待できる範囲。
- **適用条件と負担**: 効きそうな条件、実装・計算の負担、重大な限界、まだ確かめていない点。
- **次の判断**: 採用・追加検証・終了の推奨と、それを変え得る最小の確認事項。

調査だけの期待を実測の改善として扱わない。根拠が乏しい場合は、判断保留の理由が結論になる。
文献から引用した性能と、このプロジェクトで測った性能を区別する。

## 同じPDFの後半: 初見でも判断を検討できる詳細

1. **問題と手法**: 入出力、比較対象、仮説、仕組み、前提を説明する。必要な式・図・疑似コードを添え、
   記号を定義する。既存研究の再現・応用と、自分が加えた案を区別する。
2. **設計と検証**: データと分割、学習・評価の関係、実際の設定、seedと試行数、停止条件、
   指標と選択方法を示す。Kaggleでは最終指標と代理の目的関数・報酬を区別する。
3. **結果と解釈**: 同条件の比較表や図、失敗・中断、ばらつき、反証や別の説明を含める。
   少数試行や選択による偏り、保留データで未確認の点を明記する。
4. **適用と限界**: どの条件なら勧められるか、何がまだ言えないか、次に何を検証すべきかを書く。
5. **出典と再現情報**: 主張に対応する一次資料の書誌情報・URL・版や参照日を載せる。
   実行、コードと適用済み設定、データ・評価、成果物を特定する情報を添える。

重要な条件・結果・限界はPDF本文に含め、再現の細部だけをMarkdownや実行マニフェストへ委ねる。
ローカルの成果物はプロジェクト内の所在と利用可能性を示す。参照だけで説明を済ませない。
取得できない資料、保存されていない変更、失われた成果物は欠落として残す。

## LaTeXで生成し、PDFを確認する

プロジェクトに既存の文書設定があれば使う。なければ利用可能なエンジン・フォントを確認する。
日本語では、たとえばLuaLaTeXと `ltjsarticle` を使える。参考となる最小の構成:

```latex
% !LW recipe=lualatex
\documentclass[a4paper,11pt]{ltjsarticle}
\usepackage[margin=23mm]{geometry}
\usepackage{amsmath,booktabs,graphicx}
\usepackage[hidelinks]{hyperref}
\begin{document}
% 冒頭の判断、手法の説明、検証、限界、出典をここに書く。
\end{document}
```

自分で作った一時ディレクトリにtex・図・ビルド出力を置く。既存の利用者のtexを削除しない。
上記の例なら、一時ディレクトリで次のようにビルドできる。

```bash
latexmk -lualatex -interaction=nonstopmode -halt-on-error -file-line-error -outdir=build report.tex
```

本文を推敲し、重要な数値・単位・比較条件・引用を元の根拠と照合する。ビルド後は未解決の参照、
欠落文字、はみ出しの警告を確認し、`pdftotext` 等で文字を、`pdftoppm` 等で全ページの描画を確認する。
冒頭の判断が最初のページに収まるか、図表・式・日本語が読めるかも確かめる。
修正したら再ビルドして最終PDFを再確認する。生成環境が不足する場合は不足と未完了部分を報告し、
未実行のビルドやMarkdownを完成したPDFとして扱わない。

## 固定した版を届ける

既存の納品先を使う。なければ `reports/<topic>/<method>-<version>.pdf` のように、手法と版を識別できる
名前にする。作業中のPDFは差し替えられるが、納品済みのパスを再利用しない。
訂正・追加実験で再報告が必要になったら、理由を添えて新しい固定版を作り、入口からは各手法の
現在の1本へ案内する。旧版を編集・削除せず、置き換えた版との対応を補助記録に残す。

最終成果物はPDF。検証済みPDFを保存先へコピーして開けることを確認してから、自分で作った
一時tex・補助ファイルを片づける。texを編集用成果物として納品する必要はない。
科学的な根拠を残すためのコード・設定・ログ・データまで削除しない。
入口のMarkdownは手法名とPDFのリンクにとどめ、別の総合レポートを読む前提にしない。
