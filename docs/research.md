# 調査と採用した考え方

確認日: 2026-10-16。これは設計の根拠を記録する文書です。
現在の構成と使い方は、[Architecture](architecture.md)と[README](../README.md)が正本です。

## 公式仕様

[Agent Skillsの仕様](https://agentskills.io/specification)は、名前と説明を持つ
`SKILL.md` を入口とし、必要に応じて参照文書やスクリプトを同梱する形式です。
本プロジェクトはこの形式を使い、プロジェクト文書に独自の必須schemaは設けません。
検証には公式リポジトリの
[skills-ref](https://github.com/agentskills/agentskills/tree/69ef37e9424c0a7ea9dd2293b559e43ec8176379/skills-ref)
を使います。これは参照実装であり、判断品質を保証するものではありません。

[OpenAIのSkillsガイド](https://learn.chatgpt.com/docs/build-skills)は、
用途が明確なdescription、必要な部分だけを読む構成、指示中心の実装を勧めています。
ローカルでは `.agents/skills/` とシンボリックリンクが利用できます。
ここでは各Skillを単独でコピーできる形にし、特定モデルや他のSkillへの必須依存を設けません。
Codex用の表示情報だけ `agents/openai.yaml` に置きます。

## 既存ワークフロー

[Planning with Files](https://github.com/OthmanAdi/planning-with-files)は、
タスク計画・発見・進捗をファイルへ保存し、セッション外に状態を残します。
複数タスクでは対象の計画を明確に選び、再開時にGit差分も確認します。
この考え方は再利用し、すでに運用されている計画はそのまま正本にします。
導入先に計画管理がない場合には、更新箇所を増やさずタスクごとに1ファイルで始めます。
フック、セッション履歴の収集、独自の完了ゲートは取り込みません。

[Superpowers](https://github.com/obra/superpowers)の設計・実装計画と検証の分離は、
複雑な開発に役立ちます。本プロジェクトは開発プロセスを置き換えず、既存の計画や
チェックリストに再開に必要な状態を補います。完了した計画を永久に残す方針にはせず、
必要な知識へ反映した後にGit履歴へ退役させます。

ユーザー指定のPrivateプロジェクト3件も読み取り専用で調査しました。
文書、コード、数値、実行ID、保存先は転載していません。そこから得た一般的な判断は、
現行構造・比較実験・知見を分けること、設定と実行証拠を結ぶこと、生成時と解析時の
revisionを区別すること、未完了の設計を現行構造へ混ぜないことです。
各プロジェクトの個別ルールを汎用Skillsの必須条件にはしていません。

## この構成を選んだ理由

記録と統合は判断の目的が異なります。記録時には個別の事実と再現条件を保ち、
統合時には関連する根拠を横断して、同じ説明を減らします。再開はそのどちらとも異なり、
未完了作業と外部ジョブの現在地を復元します。この3つを独立したSkillにしました。

文書を減らす際も、失敗した条件や唯一の再現手順を失ってはいけません。
Gitにあるのは追跡済みファイルの履歴です。外部成果物、未追跡メモ、未保存の変更を
Gitが保護しているとは扱わず、削除できる根拠を個別に確認します。
