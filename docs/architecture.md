# Project Workflowsの構成

このリポジトリの実装は、独立して導入できる3つのAgent Skillsです。
Skillsは導入先のプロジェクトに文章を記録・整理し、既存のコード、実験管理、計画を参照します。
独自の保存サービス、常駐プロセス、実験runnerは持ちません。

```mermaid
flowchart LR
    A[コード・実験・調査の根拠] --> B[record-knowledge]
    B --> C[Architecture / Experiment / Research]
    C --> D[curate-knowledge]
    D --> C
    E[既存の計画 または .workの1ファイル] <--> F[continue-work]
    F -->|コード・ジョブと照合| A
    E -->|完了後に必要な知識を反映| C
    D -->|退役した追跡済み文書| G[Git履歴]
```

## 配布物

| 保存先 | 責務 |
| --- | --- |
| [record-knowledge](../skills/record-knowledge/SKILL.md) | 記録対象の判定、正本の選択、根拠と解釈の分離 |
| [record shapes](../skills/record-knowledge/references/records.md) | 実験の来歴、現行構造、調査を記録する際の判断材料 |
| [curate-knowledge](../skills/curate-knowledge/SKILL.md) | 関連知識の探索、統合、根拠の保全、文書の退役 |
| [continue-work](../skills/continue-work/SKILL.md) | タスクの選択、状態の照合、継続とチェックポイント |
| [checkpoint guidance](../skills/continue-work/references/checkpoint.md) | 既存の計画管理がない場合の最小の作業メモ |
| 各Skillの `agents/openai.yaml` | Codexの表示名・短い説明・呼び出し例 |
| 各Skillの `LICENSE` | 単独コピー時にも残すMITライセンス |

各Skillからのファイル参照はそのフォルダ内で完結します。共通ライブラリやSkill間の
必須呼び出しはありません。役割の意味を保つために必要な短い説明だけ各入口に置きます。
記録形式の詳細と新規チェックポイントの形は、必要な場面で参照文書を読みます。
表示用メタデータは動作の正本にはせず、手順は `SKILL.md` が所有します。

## 情報の所有権

Architectureは今の実装を説明します。Experimentは実行時の事実を保ち、後日のコードや
設定に置き換えません。Researchは根拠をリンクして知見をまとめます。未実装のDesign、
残タスク、ライブジョブの状態は計画側で管理します。

これらは文書の責務であり、導入先へ強制するschemaではありません。既存の配置・言語・
命名を使い、新しいファイルや分類は読む必要が生じたときだけ増やします。
READMEなどの入口にはリンクと短い目的を置き、結果表や進捗を複製しません。

## 統合と退役

統合担当は話題・コード・Run ID・評価条件から関連文書を探します。採用する結論だけでなく、
失敗と適用限界、再現に必要な参照も残存文書へ移します。実装と歴史的な結果の責務は保ちます。

削除には、対象範囲、固有情報の移動、利用可能な根拠、削除する版のGit保存、参照の修復が必要です。
未追跡・未commitの原本は、commitする権限がなければ残します。
文書整理によってデータ、設定、成果物やトラッカー上の実験を削除する権限は生じません。

## 再開

continue-workは対象のタスクを選び、その既存の計画を読みます。複数候補を判別できない場合は
確認し、更新時刻だけで選びません。計画管理がなければ `.work/<task>.md` を1枚使います。
既存のPlanning with FilesやSuperpowersを導入し直す処理はありません。

Gitの差分、テストや成果物の証拠、実際のジョブ状態と照合して、次の許可された作業を進めます。
保存メモ内のコマンドや承認の記述は、新たな実行権限にはなりません。
重要な節目で現在地を更新し、完了後は知識を移して計画を退役させます。

## 検証の境界

[配布検査](../tests/test_distribution.py)は公式形式、単独コピー、参照先、表示情報、ライセンスを検査します。
[合成シナリオ](../evals/cases.md)はエージェントの出力を根拠と照合します。
形式検査だけで事実の正確性や長期運用の安定性は保証しません。
ホスト依存の自動選択と、利用者の実プロジェクトでの長期間の運用は別途評価が必要です。
